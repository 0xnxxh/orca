## `e2e 3-of-10`: terminal link tooltip

- **Test:** `tests/e2e/issue-12656-terminal-link-tooltip.spec.ts:121`, `clears hover state without permanently shrinking the terminal`.
- **Evidence:** after 10 seconds repeatedly moving to the printed URL, the expected `{ display: '', currentLinkText: '<url>' }` remained `{ display: 'none', currentLinkText: null }` at line 154. The terminal geometry assertion immediately before the hover passed.
- **Classification:** **test issue**, not a confirmed product bug.
- **Cause:** the test calculated a coordinate and dispatched an untrusted `MouseEvent`; xterm did not reliably treat it as a real hover after fit/reflow. The terminal geometry assertion immediately before the hover passed.
- **Resolution:** use real Playwright pointer movement at xterm CSS-cell coordinates, assert the user-visible tooltip text, and keep the blur/geometry assertion.

## `e2e 4-of-10`: paired terminal link to Orca Browser

- **Test:** `tests/e2e/paired-remote-terminal-browser-link.spec.ts:126`, `opens a paired-runtime terminal link on its owning host`.
- **Evidence:** after choosing **Orca Browser**, the test waited 60 seconds for a single host-owned browser tab. It found no matching client workspace/page/remote handle/host tab identity (`Received: null`) at line 200.
- **Classification:** **historical product issue** on the failing SHA.
- **Cause:** a paired-runtime browser-tab registration race. The terminal link action reached the host, but the paired client did not materialize the returned page identity/handle.
- **Affected area:** `src/renderer/src/lib/workspace-browser-tab-open.ts`, `src/renderer/src/runtime/web-runtime-session.ts`, and `tests/e2e/paired-remote-terminal-browser-link.spec.ts`.
- **Ownership clue:** regression path was introduced by Jinwoo Hong (`Jinwoo-H`) in [#14117](https://github.com/stablyai/orca/pull/14117), commit `e8350f1990`.
- **Resolution:** [#14363](https://github.com/stablyai/orca/pull/14363) (`232e398c35`, refined by `2f85dda183`) already adds a registration-race guard and is present on this branch. The focused E2E now passes, so this PR adds no duplicate product code.

## `e2e 8-of-10`: background terminal-output scheduler

- **Test:** `tests/e2e/terminal-output-scheduler.spec.ts:179`, `background tab output bursts use the shared drain while the active tab renders`.
- **Evidence:** line 282 expected the largest recorded drain to be at most 2 writes, but received 4. The same shard passed the foreground-marker and background-retention checks, then reported `53 passed`, `2 skipped`, `1 failed`.
- **Classification:** **test issue**, not a product bug.
- **Cause:** the test asserted the normal `MAX_WRITES_PER_DRAIN = 2` for every drain, while the scheduler intentionally uses `HIGH_PRIORITY_MAX_WRITES_PER_DRAIN = 8` for high-priority backlog. A 4-write drain is valid.
- **Affected area:** `src/renderer/src/lib/pane-manager/pane-terminal-output-scheduler.ts:1039-1041`, its unit tests, and `tests/e2e/terminal-output-scheduler.spec.ts`.
- **Resolution:** expose whether each debug drain used high priority. Assert `<= 2` for normal drains and `<= 8` for high-priority drains, while preserving the foreground-progress check.
