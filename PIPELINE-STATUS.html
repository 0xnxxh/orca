PR shape decision — the #14350 cluster

Four PRs on root-cause boundaries, not one and not seven

The brief asked whether the five-ticket cluster is one root cause with five faces. Having read all seven #14350 tickets together against the code: it is not. They split into four independent causes, and collapsing them into one PR would couple unrelated risk while a five-way split would fragment one genuine shared cause.

  • PR A — 4449 + 4491 (P0): retirement identity must survive repo re-add. One cause (tombstones keyed to a rotating identity), two host axes. In progress.
  • PR B — 4471 (P0): host-side enforcement independent of client provenance. A wire-compat concern, different fix site (create path), overturns a documented decision.
  • PR C — 4472 + 4473 (P0/P1): the backfill scan itself — WSL distro coverage plus a deadline, failed-Promise eviction, and routing UNC reads through the bounded WSL gate.
  • PR D — 4479 + 4480 (P2): two small mobile suggestion-surface defects, both cosmetic, naturally one mobile PR.

The obvious fix for 4449 is wrong — flagged to the fixer

"Key retirement storage by namespace instead of repo.id" is explicitly rejected in PR #14350's own body: the namespace derives from workspaceDir, nestWorkspaces, worktreeBasePath and repo.path, so keying storage on it orphans every retirement the moment a user toggles any one of those — far more common than remove/re-add. The fix must keep repo.id as primary storage and additionally mirror into the path-derived namespace (exactly what the code already does for remote repos, gated off for local at the read side, line ~185, and the write side, line ~216). Both axes then hold.
